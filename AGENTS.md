# AGENTS.md

Operating notes for agents (and humans) in this repo; included by `CLAUDE.md` via `@AGENTS.md`. Every claim is true of the tree NOW; change the line describing a change in the same commit. Past incidents belong in git history, narrative in `README.md`.

Deep rationale for the rules below lives in gm memory; each `-> recall` line retrieves its memo.

## What casey is

A thin, domain-configurable structured-intake orchestrator over WhatsApp/Discord (the generic helpdesk demo ships no domain; a deployment supplies its whole domain through `CASEY_CONFIG_DIR`, see Configuration architecture).

### Contact access ladder (`src/contact-tiers.js`)

- `TIER_ORDER` (low->high) is the `tiers` key order in `CASEY_CONFIG_DIR/domain.yml` (the deployment lists its own ids); code addresses rungs as `TIER.reporter`, `TIER.field`, `TIER.specialist`, `TIER.operator`. Every permission question asks "at least rung N" (`atLeast`/`canQueryCases`), NEVER "exactly N". `resolveTierValue` is fail-closed: missing/empty/pre-migration/corrupt maps to the LOWEST rung. The `specialist` rung holds EXCLUSIVE authority to move a report to done. Per-tool minimum rung is `TOOL_MIN_TIER` in `case-tools-gates.js`, keyed by the visible tool names that `domain.yml` `tool_names` produces. Ownership gates on the INTAKE record tools (`case_switch`, `case_update`, `case_observe`, `case_transition`, `case_link_suggestions`, `case_split`, `case_health`) are scoped by `!ownsCase(...) && !canQueryCases(ctx?.tier)`: a team member may act on ANY public report, a reporter only on its own. Two things stay closed for a non-owner team tier -- a DONE-stage move (custody: assigned, unassigned or handed-off only) and `case_update`'s `assignee` field -- and `case_switch` refuses a `channel:system` target; `writeGate` still guards a multi-ref message for team tiers, minus its focus ritual. The ASSIGNED-worker desk tools keep the stricter `authorityOn`/`deskAuthorityOn` gate, because they disclose the reporter's number and message them.
- Only an admin may grant the operator OR specialist rung (`grantableBy(isAdmin)` is the one filter every grant route uses). `canSignOff` is EQUALITY on purpose. Stored strings are `contact.tier` / `case.reporter_tier`; a different human-facing WORD is only a label via `report-fields.yml` `dashboard_ui.tier_labels`.
- The dashboard sign-off gate refuses in order: technician authority, mandatory minimum, then `signoff_diagnosis`. `mandatory_minimum` is enforced at three code points and gates the AGENT tool surface only, so a console operator closing is not asked. `selfCheckLoadBearingPromptContent` throws if an elevated instruction is missing or leaks downward. A record is held only by someone who can act on it; demotion or deleting a field login releases every open record.
- `diagnosis_status` (confirmed|suspected|ruled_out) is an optional `signoff_diagnosis` field: only a schema that lists it requires it (`report-shape.js` demands options drawn from those three). Reports with it ruled_out leave every disease count and surface only as the k-floored `ruled_out` total; suspected rows carry `row.status` and feed `by_status`; a missing status counts as confirmed. `CaseStore.transition` clears the sign-off fields on any done -> not-done move into the transition event's `data.previous_diagnosis`, so the next sign-off restates them.
- Roles arrive only by operator assignment (`POST /api/contacts/:id/tier` or `/register`; `normalizeMsisdn` refuses an SA number that is not 27+9 digits) or a one-time code consumed AFTER admission and BEFORE any turn; the model never sees the code. WRITE refuses an unrecognised tier, READ coerces a corrupt one to the lowest rung.

## Configuration architecture (`src/config-loader.js`)

- `CASEY_CONFIG_DIR` is REQUIRED and wholesale-REPLACES all config: it holds `domain.yml`, `thatcher.config.yml`, `report-fields.yml`, `persona.cjs`, `vocabulary.yml` and `portal-defaults.yml`, plus the optional `pack.cjs`, `external-schema.cjs` and `dashboard.yml`. There is no bundled default and no repo-root `thatcher.config.yml`; each deployment keeps its config directory in its own repository. `CASEY_ROUTER_DIR` points at the deployer's router script bundle; when unset or missing, `/api/router/bundle/:name` answers 404 and the process keeps running. `router-bundle.yml` in `CASEY_CONFIG_DIR` declares that bundle: the script names served and allowed, the apply script, the seed script, the TLS files, the root certificate (file, common name, SHA-256), the device script that holds the globals and the names of those globals, the TLS mode, the bootstrap title and log prefix, and the router id prefix. Without it, router provisioning answers 503 and bundle requests 404. `portal-defaults.yml` also requires `admin_router_cookie` (the cookie that names the router an admin is viewing) and `phone_storage_key` (the browser storage key the login page uses to remember a phone number).
- `domain.yml` (required) declares the domain: `tiers` (logical keys `reporter`, `field`, `specialist`, `operator` mapped to stored tier ids, in ladder order), `tier_labels`, `admin_only_tiers`, `observation_form` (the pack form casey reads) and `tool_names` (generic tool name to the name the model sees). `pack.cjs` exports the observation pack read by `provenance-wire.js`; `external-schema.cjs` exports `EXTERNAL_SCHEMA`, `FIELD_CROSSWALK` and `NO_CASEY_COUNTERPART` read by `src/sync/external-schema-map.js`; `dashboard.yml` is returned as `loadDomainConfig().dashboard`. Every file is read through `loadDomainConfig()`, never imported. The lint trust-boundary rule covers `pack.cjs` and `external-schema.cjs` when `CASEY_CONFIG_DIR` is set.
- `report-fields.yml` declares `fields[]` (flags `critical_for_visit`, `append`, `never_inferred`, `system_set`, `severity_signal`) plus the gate/signoff/area blocks (`mandatory_minimum`, `signoff_diagnosis`, `area_field`, `geo_fields`) and `dashboard_ui` (DISPLAY only). `persona.cjs` declares prompt TEXT (`agentName`; `noticeVersion`/`noticeAnchor`); `caseSystemPrompt` owns STRUCTURAL logic. `vocabulary.yml` is the one file of words people read.
- `src/store/report-shape.js` is the single choke point: every derived shape constant is exported there and every consumer imports it. `deriveReportShape(reportFields)` is a pure function for MULTIPLE schemas per process.

## Architecture

casey composes four git submodules under `deps/`: `freddie` (agent runtime, Cordis plugin tree, NOT npm-importable), `acptoapi` (LLM chain), `thatcher` (+ `busybase`; system of record: `case`/`event`/`contact`), `anentrypoint-design` (UI). Run `git submodule update --init --recursive` after a clone.

- `bootCasey()` calls freddie's `boot()`; casey mounts tools as `defineTool()` on `ctx.tools`, an `LlmAdapter` on `ctx.llm`, and the WhatsApp webhook on `ctx.webServer` at `CASEY_WEBHOOK_PORT` (`127.0.0.1:4001`); keep clear of the dashboard's 4000 or it dies with EADDRINUSE/exit 44.
- THE SAME WEBHOOK IS ALSO ON THE DASHBOARD'S PORT (`routes/whatsapp-webhook.js`, ADDITIVE), registered FIRST ahead of `compressResponses`, `express.json()`, session middleware, CSRF and `authGate()`, so it is exempt and carries its OWN `X-Hub-Signature-256` over the RAW bytes.
- SECURITY: `installToolAllowlist(agentCtx, allowedNames)` is the real boundary, installed PER-AGENT; keep BOTH gates (`system-prompt/assemble` hides non-allowlisted schemas, `tools/pre-execute` denies dispatch by name). `src/case-tools.js` is the single source of truth for WHICH case tools exist and in what order.
- `adapter.send` is the ONLY route an agent reply has to a contact; `bin/send-reply.js`'s `makeSendReply` REJECTS when the channel has no adapter.
- External sync (`src/sync/`, see `EXTERNAL-SYNC.md`): correlation writes only `external_link` 'proposed'; `apply-link.js` fills EMPTY `case.report` from a CONFIRMED link only.
- `CASEY_PUBLIC_SITE_DIR` (absolute dir with `index.html`) adds an optional public landing page: `/` serves it to a request without a valid session (a session still gets the console), `/app` (always) is the console entry, `/site/` serves its assets pre-auth (GET/HEAD only, no dotfiles, no symlink escape, nosniff); boot throws on a bad dir.
- Operator console (`src/dashboard/`): its imperatives (shell caching, auth and route order, printables, console UI, stylesheets, backup) live in `src/dashboard/AGENTS.md`, each with a `-> recall` for the reasons; read it before touching the shell, `auth.js`, `roles.js` or the SPA.
- Agent runtime (`src/agent/`): one live agent per `case:<id>`; eviction is `CASEY_AGENT_IDLE_TTL_MS` (default 3h), never a count cap, always RESUME-before-CREATE. `CASEY_LLM_CONCURRENCY` (default 4, 0 off); `CASEY_LLM_REQUIRE_MODEL` pins the one allowed model.

## Supply-chain integrity

Composed deps come from each project's `main` tip with no registry pins. Every session and dependency touch: dispatch `scan_deps {"full":true}` before trusting freshly resolved `node_modules`/submodules. `failCount>0`/`blockedCount>0` = live evidence. `postinstall` must keep its exit-code split (setup steps tolerant; the scanner's exit code straight to npm). Submodules always track main, never a detached commit (`git reset --hard origin/main`, not `git pull`); `npm run check-submodules` checks branch/dirty/ahead-behind.

## Dev workflow

`.gm/dream-rsi/` is untracked: it is gm's transient replay and strategy state, the same class as `.gm/exec-spool/`. Tracking it made every gm session show "submodule has modified content" in the projects that consume casey.

`scripts/omni-asr.py` is installed by the deployer's local speech-to-text setup script; casey does not install it. It is called by `src/hooks/local-stt.js` as `python omni-asr.py <model-dir> <16 kHz mono wav> [threads]` and prints one JSON line `{"text": ...}`. The CTC model needs no language setting: one model covers more than 1600 languages.

`.env` is written by `casey init` (`bin/casey-setup.js`) and holds channel tokens, the dashboard secret and `CASEY_SESSION_SECRET` (read by `src/dashboard/auth.js`). It is never committed.

`scratch-*.mjs`, `scratch-*.log` and `.scratch_audit/` are untracked session probes. Casey keeps no standing test files, so a probe worth keeping moves to a committed path deliberately, not by surviving untracked at the root.

`.claude/*` is excluded by glob, not the directory itself: git does not descend into an excluded directory, so excluding `.claude/` would stop `!.claude/workflows/` from re-including the reusable project workflows.

gm runtime state under `.gm/` is ignored per entry. The entries `.gm/prd.yml`, `.gm/claim-audit-fired` and `.gm/memories/.flat-export-done` were added after the org-wide gm cleanup removed plan and runtime files from tracking, to keep `git status` clean. `.agentplug-kv/` and `.agentplug/` hold the shared agentplug daemon's own transient state at the repo root. `.flatspace-clone/`, `.scratch_tmp/` and `bbwork/` are scratch clones and work directories that concurrent tool dispatches spawn in this directory; none of it is casey content.

The lockfile in the tree is `bun.lock`, which matches `package.json` (10 dependencies, express 5.2.1). Nothing in casey invokes bun, so it does not pin the documented `npm install` path. `package-lock.json` is not ignored, but `npm install --package-lock-only --ignore-scripts` fails with "Cannot read properties of null (reading 'package')" because of the `file:deps/*` dependencies (checked 2026-11-09), so no npm lockfile can be produced until that is fixed upstream or the `file:` dependencies are restructured. It matters because `SUPPLY-CHAIN-SCAN-INSTRUCTIONS.md` names an unpinned install as the route by which a compromised release reaches you automatically.

`gui-check` and `gui-check-vocab` require `CASEY_CONFIG_DIR` and read fixtures from it; there is no fallback config.

`.gitleaks.toml` is not in casey: the secrets scan runs gitleaks with its default rules. A deployer keeps its own gitleaks config in its repository.

`npm install` runs `postinstall` -> `install-freddie-deps.mjs`, `link-deps.mjs`, `install-hooks.mjs` (tolerant; a failure continues the install degraded), then `scan-deps.mjs` (its exit code passes straight through); if a step failed, run `node bin/casey.js doctor`. `npm run lint` is the dependency-free gate to run before pushing (gate list in `scripts/lint.mjs`); `gui-check` is NOT part of it. No automated test suite; verification is manual/live.

`.github/workflows/secrets.yml` runs gitleaks only (full-history) on push/PR; the tracked `hooks/pre-push` runs `npm run lint` before a push (skips when node or the scripts are absent; `git push --no-verify` escapes).

`bin/casey.js` loads `.env` BEFORE it dynamically imports `bin/casey-cli.mjs`. `--help`/`-h` is answered from `USAGE` BEFORE the handler runs, and every one-shot command ends through `closeAndExit` (releases the sqlite handle first).

### Live reload: two mechanisms, one boundary

- Cordis HMR owns the plugin trees; a full drain-and-respawn owns everything HMR cannot replace. A restart does NOT cost the Discord gateway backlog; a stored session with no bot identity is NOT resumed.
- Supervisor (`src/supervisor.js`, xstate `src/supervisor-machine.js`) forks the worker, never re-imports app code; exit 44 (dashboard EADDRINUSE) is config-fatal and never restarts. `bin/worker.js`'s crash net sends `WORKER_MSG.FATAL` on any uncaughtException/unhandledRejection. `CASEY_EXTRA_DASHBOARD_ROUTES` names a module whose default export `(app,{store})=>void` mounts extra dashboard routes.

Editing/pushing a composed dependency (`deps/thatcher`; same for acptoapi/design): fix, commit+push inside it, then `git add deps/thatcher && git commit -m "chore(deps): bump thatcher submodule pointer" && npm install`; `deps/freddie` instead needs `pnpm install` inside it then `node scripts/link-deps.mjs`. AUTO-UPDATE (default on; `--no-auto-update`, `CASEY_AUTO_UPDATE=0`) leaves a dirty/divergent tree alone.

## Timeout coordination (live turn guarantee)

Four independent layers; all four must agree on an outer bound. Every live turn ends with a real reply OR a truthful status message.

- L1: `CASEY_TURN_HARD_DEADLINE_MS` (120000) total retry budget for a live first-attempt inbound; `CASEY_TURN_SOFT_DEADLINE_MS` (25000) picks fallback tone; `CASEY_LLM_TURN_TIMEOUT_MS` (120000) per-attempt ceiling.
- L2: `ACPTOAPI_CHAIN_LINK_TIMEOUT_MS`; acptoapi's SHIPPED DEFAULT IS 120000, so set it explicitly. doctor flags a per-link timeout not comfortably below the per-attempt budget.
- L3 readiness/discovery. L4 background re-drives are NOT subject to the hard deadline, silent on degrade, cap 5 per msgId before dead-letter. A guaranteed-fallback message is not an answer (`completesTurn` excludes `data.guaranteedFallback`).
- Ordering: hard >= soft; hard >= per-attempt; per-attempt > per-link; per-link >= readiness/discovery. Exactly ONE `data.degraded_turn` row per degraded turn.

## Design principles (preserve these)

- No mocks/fallbacks/stubs -- only singular mechanisms and loud errors. A degraded turn never fabricates case content (exception: a live first-attempt turn still degraded after its budget sends a truthful status; a background re-drive stays silent).
- Personal data goes only to processors casey can hold to a no-training policy (`CASEY_LLM_DATA_POLICY`, default `zdr`; `allow` disables the guarantee). The bot never contacts anybody; everybody contacts the bot (`CASEY_PROACTIVE_SENDS=off`); ONE gate at the sending seams. A case is keyed per contact, not per channel.
- Areas/hand-over/day: resolution is EQUALITY (`resolveArea`; no gazetteer/fuzzy match; unmatched -> `unmappedAreas`); `autoAssignByArea` runs once per OPEN UNASSIGNED record after a write touching area/location. An area may carry an optional `lat`/`lon`; when no spelling matches, the nearest placed area within `areaNearestMaxKm` (`thresholds.js`, default 150 km) is assigned, a name match always winning over distance. It also fires after `case_report` writes lat/lon, because the report-merge hook runs BEFORE the coordinates exist.

### Inbound turn pipeline (`src/hooks/`)

- Admission (`admission.js`) claims each contact SYNCHRONOUSLY; a burst is BUFFERED raw and replayed; a rate-limited inbound sends no reply. ONE agent reply per message GROUP: after the first message's intake (STT included, before the turn clock) `absorbBurst` waits `CASEY_BURST_SETTLE_MS` (2500, only when it carries media) and folds every buffered non-STOP/HELP message into the same turn; each outbound/draft carries `data.in_reply_to` (the group's wamids), `sendAgentReply` and the pre-turn check refuse a second reply keyed to any of them (a `delivered:false` reply does not count), a buffered redelivery is dropped by wamid, and the 'still working' fallback is sent once per group and never counts as the reply. Opt-out intent (`detectContactIntent`) reads TYPED text only (`typedText`); transcripts never count as STOP/HELP, an unheard (failed, low-confidence, unsupported-language) voice note is logged on the inbound (`stt_verdict`, `stt_failure`) and the timeline and never merged into the text, and `replay-message.js` rebuilds a redriven voice note from `typed_chars` + `stt` without transcribing again. Agent-turn gates (`turn-attempts.js`) never leave a reply blank; `reply-judge.js` adjudicates against named fault shapes.

- Voice notes (`src/stt/`): `CASEY_STT_ENGINE=google` makes Google Cloud Speech-to-Text v2 (default `chirp_3`, location `us`, `language_codes=["auto"]`, plain REST with the VM service-account metadata token, no key, no SDK) the primary engine, with local whisper/omnilingual only as a rescue when Google is unreachable; notes over 50 s are cut on silence with ffmpeg (max `CASEY_STT_MAX_SECONDS`, whole intake bounded by `CASEY_STT_BUDGET_MS`, all BEFORE the turn clock). With Google, `CASEY_STT_SPECIALISTS` (xh, zu, af BuzzASR endpoints) is run in parallel on the full note after Google (not for Sepedi `nso`), and `stt/arbitrate.js` makes one LLM call choosing among the candidate ids (falls back to Google on error or bad JSON); `data.stt_candidates` keeps each engine's metadata and `has_text` only (no transcript text; POPIA minimisation, the chosen transcript is the inbound text) and `data.stt_choice` the decision's fixed fields (the LLM reason stays in memory), and transcripts still never count as STOP/HELP. The transcript is HEARD text: `stt/readback.js` makes the model read back species, counts, location and diagnosis and wait for a yes before recording, and refuses to act on low-confidence or unsupported-language audio; failures become a truthful per-kind system note, `stt_*` counters are on `/api/health`, and `scripts/stt-eval.mjs` reports WER per language. Opt-in voice replies: `CASEY_VOICE_REPLIES=google` plus case tag `voice-replies`, only af-ZA and en-GB have voices.

### Top-level modules (`src/`)

- `case-store.js` is the single chokepoint over thatcher; open-case lookup uses a `status:{$in:openStages}` ALLOWLIST, never `$ne:'closed'`. `retention.js` is OFF unless `CASEY_RETENTION_DAYS` is set, defaults ARCHIVE, frees no sqlite bytes (soft-delete).
- Resume vs drain (`casey-resume*.js`, `casey-drain.js`): a crash's half-done turn vs an outage's unstarted one -- DO NOT merge.
- `case-machine.js`/`supervisor-machine.js` are PURE xstate TRANSITION-VALIDATION authorities (no actors). `CASEY_CRASH_LIMIT` has no "off" (non-positive -> 5).
- `report-digest.js` (`casey report-digest`) builds the monthly aggregate CSV and text from `reports-map.js` exports only (k-floored); `--post` goes solely to `CASEY_ALERT_WEBHOOK` (operator endpoint, never a contact). An area may carry an optional `district` label; `reports-map.js` maps the stated area to it by EQUALITY (unmapped -> `unknown`) into `by_district` (k-floored), carried in the CSV `district` view and the digest. `--out-dir <dir>` (exclusive with `--out`) writes both files atomically (temp + rename); the console lists `<store.dataDir>/digests` (`routes/report-files.js`, filenames allowlisted by `casey-digest-YYYY-MM.(csv|txt)`), so the caller passes `<cwd>/data/digests`.
- `privacy.js` is the ONE k-anonymity floor; `format.js` MARKS (never strips) bidi/invisible chars; `log-scrub.js` redacts secrets from stdout/stderr; `llm-data-policy.js` (default `zdr`) drops providers without a no-training guarantee.

## Security invariants (do not regress)

- WhatsApp inbound is HMAC-SHA256 verified when `WHATSAPP_APP_SECRET` is set; that secret is REQUIRED to serve WhatsApp when WhatsApp credentials exist, or anyone reaching the webhook can forge farmer messages. A bad signature answers 401; a bad verify challenge answers 403.
- No dashboard route ever returns a raw case or contact row -- only through an explicit field allowlist (`caseListProjection()`/`caseDetailProjection()`, `publicContact()`), never a spread. `external_id`, `author_key`, `contact_id` may NEVER be emitted; an operator MAY see `external_id_formatted` on a single case they opened, but the case LIST stays PII-free. `lint.mjs`'s `pii-safety` gate enforces this by dataflow; all contact-supplied text is HTML-escaped before render.
- Every contact-reachable prompt value goes through `hooks/prompt-context.js`'s `fenced()`, which neutralises BOTH `<<DATA>>` and `<<END>>` inside the value; `status`/`priority`/`case_type`/`autonomy` render bare (each validated on write). `hooks/prompt.js`'s `selfCheckFenceIntegrity` crashes boot on an unfenced interpolation.
- Field-login fence (`roles.js` `roleGate`): the gate decides on the lower-cased `/api`/`/media` prefix and refuses every spelling its exact-case table does not list; media is scoped only for exactly `/media/<caseId>/<file>` after decoding. Channel `system` cases are never a case for a field login; `agent` is never a person.
- System tags are not a team member's to touch (`RESERVED_TAG`), on both the WhatsApp tool and the dashboard field PATCH; `POST /api/cases/:id/reply` refuses an opted-out case server-side.
- A role is granted only to a number the operator typed; `sendStaffMessage` refuses text carrying a live invite code. Login is rate-limited and uniform (10 failures per (username, source), 60 per source per 15 min; an unknown username still pays the scrypt cost). Session epoch revocation forces re-login across all devices. A bootstrap admin's generated password is delivered only as a root-only file (mode 0600).
- Erasing a team member releases their work and unlinks their login. Cookie and password comparisons use `crypto.timingSafeEqual`. Soft deletes mean "deleted" is a FIELD: `t.list` filters them, `t.get` does NOT, so session middleware must check `status` as well as `disabled` + session epoch, and `deleteAccount` must bump `session_epoch` before removing the row.
- busybase opens with `journal_mode=delete`/`busy_timeout=0`, so sqlite NEVER waits -- it fails instantly with `SQLITE_BUSY`, and a concurrent reader can fail casey's writes. `src/store/busy-retry.js` is the only defence (USERLAND full-jitter retry inside a 5s budget); a spent intake budget is COUNTED.
- The service worker (`/sw.js` in `src/dashboard/server.js`) caches only the shell URLs in its precache list. Every other same-origin GET goes to the network and is never stored, so router admin pages (`/admin/routers/*`, and the paths the router fallback answers while a window is open) cannot be served stale after the window closes. `activate` deletes any cached entry outside the shell list.
- Leaflet tooltips are bound as HTML: every value interpolated into a tooltip in `src/dashboard/public/src/panels/resolved-map-leaflet.js` goes through `esc()`, because case reports supply free text.
- `scripts/gui-check.mjs` skips elements inside a closed `<details>`: nothing in them is painted, and Chromium reports a stale box and colour for them.
- Report drafts in `src/dashboard/routes/auth.js` live in sessionStorage under `casey.report.draft.<ref>`, never localStorage: the form takes a farm location, an owner's name and phone number on rural phones that get lent and shared. The draft is cleared once the server confirms the save. Mobile Chrome restores sessionStorage across an app restart, so the page shows a visible note with a "Clear my answers" control.
- Report form inputs use `--fs-body` (1rem, 16px) and `input[type=tel]` is in the same selector: iOS Safari zooms the page on focus below 16px, which pushes the rest of the form off a narrow phone screen.

casey consumes thatcher via `file:deps/thatcher`, calling operator-where directly with no fallback. busybase's `src/*.js` are gitignored bun-build outputs -- fixes go in the `.ts` sources in the busybase repo and are rebuilt there, never patched casey-side.

- Store write guards (`store/guards.js`): `DERIVED_ONLY_FIELDS` (system-only) and `SYSTEM_FORBIDDEN_FIELDS` (the system actor never writes `report`/`summary`/`subject`); `installVersionGuard` REFUSES a raw JS number under `expectedVersion` BEFORE the write. `toStorable()` is the required coercion. Provenance never downgrades (`canReplace`); `raw-log.js` is append-only and rotates by ARCHIVING (never truncation). `pack.cjs` in `CASEY_CONFIG_DIR`: only `observationForms[domain.observation_form].fields` is read at runtime.

## Conventions

- ASCII only in source and docs -- no arrow/box/bullet/check glyphs, emoji, em-dashes, curly quotes, combining marks (use `->`, `-`, `[x]`/`[ ]`, plain quotes, words; code operators exempt). `npm run lint`'s `ascii` gate enforces this.
- ES modules (`"type": "module"`), Node >= 22. Do not add a test file or mock-heavy unit suite.
- thatcher's sqlite handle is cwd-bound and primed at init. The real file is `<cwd>/data/db.sqlite`, not `app.db`. Re-importing the accessor forks a second handle.
- `bin/secrets-exec.mjs` loads a Google Secret Manager manifest (`src/secrets/loader.js`, pinned numeric versions, fail closed -- `"latest"` is refused), starts the child with the secrets in ITS env only (nothing written or printed), and exits 78 (EX_CONFIG) without starting it if any secret fails to load.

- Opt-out is two-step: the first exact STOP (or a first `case_stop`) only sets the reserved tag `stop-pending:<unix s>` plus a STOP-CONFIRM event carrying the inbound event id; the same turn is told (`bot.stop_confirm`) to ask for confirmation. A later exact STOP within 24 h opts out; any other message cancels it (STOP-CANCELLED); `case_stop` opts out only from an earlier turn than the pending one, for every tier (it can only target the caller's own conversation). HELP resumes as before. See `src/hooks/stop-pending.js`.

- Team search: `case_search` (`src/case-tools-search.js`, field_worker+) is the one query tool: scope mine|area|all, state, flags, species, disease, missing, since/until (SAST day edges), near; worst-first (sent back, priority, most missing, oldest); keyset cursor `after` bound to the filters; rows carry no phone numbers and a reporter first name only on assigned rows; `case_mine`/`case_today` wrap it (assigned, open); `case_get` masks owner/fallback numbers and digit runs for team members without authority on the record and pages events by `events_before`; staff replies keep list line breaks (`normaliseReply` keepLists).

- Visit capture: `case_visit` (start/next/skip/finish, assigned only, field_worker+) walks one assigned record's missing required then visit-critical facts one question at a time; the queue lives in `contact.staff_state.visit` (idle 2 h), each answer goes through `case_edit`'s own handler (relayed provenance, never_inferred intact), skip leaves the fact EMPTY, finish writes one `VISIT SUMMARY` observation. `case_visit_log` records an `action` event from dictation (numbers copied as stated; `animals_treated_count` only when exactly one digit run); phone-shaped digit runs are replaced by `a number`. `case_edit` results carry a `readback` (`Saved: ...`); the reply judge treats it as clean. Source: `src/case-tools-visit.js`, `src/visit-state.js`.

- Field console parity: `GET /api/cases?view=mine` takes `q` (accent-insensitive, all words AND over ref, subject, summary and every report value) and `state=open|closed` (closed sorted newest first, paged by `offset`), all still inside `caseAccess`; `POST /intake` takes `expected` (prior values, append fields exempt) and answers 409 with `conflicted_fields`.

- Staff reliability parity: `contact.staff_state` (JSON, `store.mutateStaffState`) holds focus (30 min idle), the focus proposal (10 min TTL, turn = inbound message id) and per-case `seen` fingerprints, so `team-focus.js` is async and survives restarts. `stale-write-guard.js`: `case_edit`/`case_stage`/non-done `case_transition` refuse ONCE (naming fields and who changed them) when a field they touch changed since the ranger was shown the case, then the retry passes; a successful write refreshes only the keys it wrote. WhatsApp `send` chunks every text at 3800 chars (`whatsapp-chunks.js`, `n/total` prefix above 2 parts) and a retry of the same (to, text) resumes at the first undelivered part; a failed part marks the outbound `delivered:false` and `ownReplyUndelivered` tells the staff member on their next turn. Staff replies are prefixed by `staffProgressLine`; a typed ref one edit from another held record needs a confirm (`ctx.confirmRefs`). A ranger's own sighting is assigned to them on first `case_report` (`claimSelfFiledReport`); `case_withdraw_handoff` and `POST /api/cases/:id/handoff/withdraw` take a hand-off back; `case_photos` sends up to 3 stored photos through `adapter.sendImage`.

- Language, help and relay (field_worker+): `src/translate.js` is the one translator (deepseek-flash only, per-key rate limit, cache = observation `translation:<eventId>[:<lang>]`, English key unchanged); the console route and `case_translate` both call it and only ever translate a reporter's own inbound message. `case_help` returns `bot.help_*` examples by tier (technician vs ranger) and the first-time welcome once (marker event `onboarded` on the contact's own conversation; no check-in/location yet); `staffNoticeNote` tells the model to call it. `case_note_to_technician` / `case_note_to_ranger` write observations tagged `ranger-note` / `technician-note` (data.tag, text capped, phone-shaped digits replaced, never pushed) shown in `signoff_queue`, `case_review.ranger_notes`, `case_pending`/`case_my_day`. Peer hand-over (`src/relay.js`, `case_offer_handover` / `case_handover_answer`): reserved tag `handover-offer` plus a `handover_offer` event; the receiver is told via `case_pending.handover_offers`; accept reassigns under the `assign|<id>` lock, decline logs, an offer lapses after 48 h or when the record changes hands; `team_assign` stays operator-only.

- Interactive layer (staff only): a tool result `{kind:'buttons'|'list', choices:[{id,title,description?,meaning}]}` (or derived: `case_search.next` -> More, `case_pending.handover_offers` -> Accept/Decline, see `choices.js`) is lifted by `offeredChoices` and `sendAgentReply` stamps ids, appends a numbered text fallback to the stored/sent text and remembers `{id -> meaning}` in `staff_state.choices` (10 min, one answer per offer set); `WhatsappAdapter.send` posts reply buttons (3, title 20) or one list (10 rows, title 24, desc 72), or text only above 10 or with audio; when text+fallback exceeds 1024 the text goes first and the interactive body is just the numbered options. A tap arrives as `interactive.button_reply|list_reply`, becomes text = title (id in `raw`), and `tapNote` tells the model what it meant, or that it expired or was already used; ids grant nothing, every gate still runs. Button words are `choice.*` in `vocabulary.yml` (never a bare `yes`/`no` key: YAML 1.1 turns them into booleans). A bare pin from staff (`pin-query.js`) saves the check-in and offers the 5 nearest open records as a list; `case_navigate` sends a record's pin through `adapter.sendLocation` (maps link text when the channel cannot), `case_route` (`route-plan.js`) orders open assigned pinned records sent-back, urgent, reporter-waiting, then nearest-neighbour from the last check-in (straight line km only, 8 stops, pinless last).

## Durable operations notes

- Backups: write `manifest.json` into the backup directory itself, discover every tree under `data/` while skipping `db.sqlite` and its `-wal`/`-shm` sidecars, and copy/restore freddie sessions to `freddieSessionsRoot`; report an absent sessions root as missing, not failed.
- Health surface: `GET /api/health`, `/api/turns/degraded`, `/api/health/provider` and `/api/health/cases`; the sweep runs every 15 minutes with thresholds and tag definitions in `case-health.js`. Team coverage alerts fire once per rising edge only when the roster is non-empty, a breaching case exists, and zero operator replies landed in the 1h window, held durably by `AlertGate`.
- Set `CASEY_TRUST_PROXY_HOPS` to the real proxy hop count: unset, every request appears to come from the proxy and all farmers share one rate-limit bucket; too high, a client can spoof `X-Forwarded-For` past the limiter.
- The `must_change_password` gate refuses every authenticated route except `/api/change-password` (plus whoami/logout/login); do not widen it.
- Case-store writes run under a per-conversation lock plus thatcher's `_version` guard and re-read the fresh row inside the lock on conflict; `eraseContact` is journalled plan-before/DONE-after, multi-step and non-atomic, and a re-run recovers unfinished siblings from the journal.
- The agent runtime keeps per-turn mutable `toolCtx`/`systemPrompt`/allowlist cells; a tier change evicts the agent with reason `tier_changed` to force a fresh conversation, and `media-tools.js` registers no model-facing tools (internal transcribe/describeImage/synthesizeSpeech helpers only).
- Provenance ranks unknown < inferred < reported < observed < measured; `canReplace` never downgrades, and values are written only through `write-path.js` `writeObservation()`.
- A `severity_signal` field is presence-based: any stated value adds +7 to attention rank, while a numeric 0 does not count; it carries no magnitude.
- The Discord adapter persists session id, resume URL, sequence and bot user id to `<dataDir>/discord-gateway-session.json` so a restart can resume; a refused resume is counted as `gateway_gap_unresumable`.
- Never assign a record to the person whose own chat it is (`isOwnConversation`), and retention must never expire a `channel:'system'` singleton.
- The LLM records the report; casey runs no separate extraction step, so report fields come only from the model's `case_report` calls and `never_inferred` fields must stay unguessed.
- Route reply-judge and LLM-verdict branches on coined reason tokens (`farewell-gap`, `repeat-ask`, `multi-ask`), never on ordinary English phrases a verdict can contain incidentally; never compose an instruction or reply from a possibly-empty list, and offer a conditional shape's reason token only when that shape is rendered.
- Admission buffers a contact's burst raw and drops the OLDEST once `BUFFER_CAP` (20) is exceeded; every drop reason is enumerated in `dropped-intake.js` `DROP_REASONS`, and a rate-limited inbound sends no reply.
- System-prompt echo (8 or more verbatim instruction words, fenced data removed) and tool-name leak (a literal `case_*` name) are code gates decided above the judge: retry, then hold for a human; they never blank the reply or send the leak.
- Advice is always held on a spent retry budget (or replaced with a composed no-advice reply), while most other judge shapes retry then send anyway; never let a held reply leave the contact with nothing.
- Console conditional GET replays the remembered body only on 304, deletes it on any non-2xx response or missing ETag, and clears the cache on login/logout so no body crosses sessions.
- `login-gate` forces the change-password step (including the reload watcher) when whoami reports `must_change_password`, shows identical failure text for a wrong password and an unknown user, and holds a session only on a positive `whoami.authed` flag.
- `nav-config` hides an action only when its capability is explicitly false, applies the role floor before deployer nav hide/relabel config, and resolves `panelTitle` against RAW section labels.
