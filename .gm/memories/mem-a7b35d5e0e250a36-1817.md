The printed briefing, handover and management report are forms an officer fills in with a pen. An unrecorded field prints BLANK (class ds-print-blank hides the placeholder in print) because 'not recorded' eats the answer space and a location row reading that looks like a finding. Writing space is ruled with a BORDER (class ds-fill-lines), never a background gradient or box-shadow, because browsers omit background graphics from a print by default. The screen default is declared BEFORE the print block so the print override wins on source order; reversed, the screen display:none beats print display:block and no line is drawn. extraCss lands before the @media print block, not after, or a briefing body margin overrides the print rule. Line-height is deliberately unset (the old font shorthand reset it to normal; naming the kit's 1.55 would stretch every row by 13 percent and change page counts). brand.js is the single palette for every server-rendered surface: the text tone is the ground darkened one percent at a time only until it measures 4.5:1 against the lightest surface it sits on (an orange brand measures 2.50:1 raw), never the raw brand colour; ink on a fill is chosen from the fill's own luminance. Server-rendered type and spacing are a CLOSED copy of the kit's resolved values (the kit's tokens are scoped under .ds-247420 so linking its stylesheet resolves nothing, its heading clamps need a container ancestor, and the bundle is 874,759 bytes against about 14 for the public form). An unknown var() drops the WHOLE declaration silently, so scripts/lint.mjs server-css-tokens fails the build on any var() the block does not define. The icon's font-size=120 is an SVG presentation attribute, not CSS type (var() is not substituted there and /icon.svg is standalone), so font sweeps must skip it.
