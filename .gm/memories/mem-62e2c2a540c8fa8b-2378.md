registerAuth order IS the security property: session resolution, then the CSRF Origin/Referer check, then public routes, then authGate, then static mounts; reordering exposes routes. /api/sync/* is exempt from the session gate only because its bearer requireScope gates it; must_change_password locks every route except change-password. Sessions are stateless HMAC cookies with no server-side table; revocation works by bumping the account's session_epoch, which every token carries and the middleware compares live. A token with no epoch claim means 0, so shipping revocation logged nobody out. changePassword re-verifies the CURRENT password (a cookie alone must not rotate it), bumps session_epoch, and the caller MUST re-issue the cookie at the new epoch, because the bump invalidates the very token that made the request and an earlier version silently logged people out mid forced-change. deleteAccount revokes the epoch BEFORE removing the row (the session middleware also refuses status=deleted, so these are two independent gates) and refuses to delete the last enabled admin (delete is irreversible, unlike disable which the CLI can recover). session_epoch is written as a string because busybase binds every column as TEXT and a JS number under expectedVersion fails the optimistic check while the write still lands. Self-revoke uses req.caseyAccount.id, never a route param. No route accepts a bearer token or ?token=. secretary is a legacy alias of operator, accepted so old logins keep working but never created new; agent is the unclaimed marker and a login named that must never hold every unclaimed case. x-view-as is admin-only and runs read-only through roleGate. roleGate decides on the lower-cased prefix because Express matches /API/contacts to the same handler as /api/contacts and the exact-case route table then refuses every spelling it does not list. Media is exactly /media/<caseId>/<file> after percent-decoding with no dot segment, separator or backslash (a check on the raw second segment let /media/<mine>/../<theirs>/f through), served with nosniff and Content-Disposition because bytes and extension are contact-chosen and same-origin with the operator session. The viewer allowlist lists only routes proven PII-free. A write that names expected_ref different from the URL case is refused with 409 so a stale tab can never land on another case.
