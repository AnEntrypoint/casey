public/index.html rules. html and body both carry the .ds-247420 class because the kit scopes its theme presets as .ds-247420[data-theme=X]; #app keeps its own copy. body needs it because overlay-primitives (Dropdown, MenuButton, Tooltip, Popover) portal popovers onto document.body, and without it .ds-popover loses position:absolute and renders full-width at the viewport bottom. The head inline script stamps data-casey-theme before first paint, mapping a stored choice off the pre-rebrand names (paper and light to herd, ink and dark to herd-ink), else the device preference; it is the same three lines as account-menu.js storedTheme and systemTheme, which re-applies them, so any divergence self-corrects. It is data-casey-theme and never data-theme on html because the kit's theme.js owns data-theme and sets auto after its module loads (live-witnessed painting a white band behind a dark app). A second inline script copies the value down to body and #app. Never hardcode a data-theme (a light paint on a dark device for the whole multi-second module descent) and never set data-accent: the kit scopes accent presets at specificity 0,3,0, which outranks the brand palette's 0,2,0 however late app.css loads, silently repainting --accent. Link only the scope-prefixed /design/dist/247420.css bundle, never the two unprefixed source sheets, or every overlay-primitives rule is unloaded. The kit's JavaScript is reached only through the ds/ import map, with no 247420.js entry (it downloads both graphs, 355,065 of 948,256 same-origin bytes). Font preloads keep crossorigin (required even same-origin or the file is fetched twice), unlike the generated modulepreloads. The modulepreload block is injected before </head> at boot, so view-source shows tags the file lacks. The #ds-boot first-paint notice is inline-styled because the stylesheet is the slow download, sits AFTER #app so the sibling selector #app:not(:empty) ~ #ds-boot hides it with no JavaScript, and Leaflet's two parser-blocking scripts sit below it but ahead of /src/main.js so first paint does not wait on them and window.L exists before any module reads it. Service worker registration reloads onto a new worker only when navigator.serviceWorker.controller existed at register time (a first visit superseded nothing and the reload re-ran the whole module graph), captured before register() resolves because clients.claim() can land between the two; the reload waits until the person stops typing or hides the tab; update checks run on tab focus and every 30 minutes because the browser re-checks /sw.js only on navigation.
