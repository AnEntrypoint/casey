## Resolved mutable: obs-cross-case-query-correctness

Fixed queryDegradedTurns and calculateDegradationRate (degraded-turns.js) to call store.listAllEvents({kind,actor},{limit}) instead of store.listEvents(null,{limit}). Live witness: a store double implementing listEvents(caseId,opts) with the real case-store.js semantics (filters by case_id) showed listEvents(null,{limit:50000}) returns 0 rows even when 3 real events exist across 2 cases -- proving null was never treated as 'all cases'. Post-fix, listAllEvents-based queryDegradedTurns correctly returned summary.total:3 with by_reason:{timeout:1,provider:1,'retry-exhausted':1} in the same witness run. Confirmed again in the full live HTTP server witness (real thatcher CaseStore): GET /api/turns/degraded and /api/health's degradation_rate both reflect the 2 real recorded degraded turns.
