Console UI kit and webjsx traps. Dropdown triggers (account-menu, notifications-center, filters-bar) return an ARRAY rather than a vnode with children, because the kit rewrap reads child.children while webjsx stores props.children and the button renders empty. webjsx cannot morph a bare-string child or a different element type inside one unkeyed slot, so keep one element type plus keys (login-gate) and never swap a button's text mid-action (the toast-tray undo uses disabled). Btn hardcodes type=button, so login-gate needs a raw submit; array children need an explicit aria-label. Free text is wrapped in its own span or h2 with min-width:0 and bounded (MAX_LEN 4000 in format.js, with the truncation stated) because an unbreakable run inside a wrapping flex froze the renderer. Accessibility: dialog-shell restores focus by node plus signature because polls detach the opener, passes trapTab the currentTarget, calls stopPropagation on Escape (otherwise keyboard.js back() closes the case behind the dialog), and focuses once per open in a macrotask; confirmDialog needs an accessible name and a Tab trap. Nothing is stated by hue or hover-only title because staff use phones; note buttons carry per-field aria names. role=button answers Enter and Space; listitem takes no aria-selected; an empty scroll region needs a focusable child. Each screen has one h1 (view-title); content-swap panels render the body only because app-view owns the title and back control; never register a panel named map. case-row stays off the kit Row so active, selected and keyboard-focused states stay distinguishable.
