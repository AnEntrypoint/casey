In casey, only an admin may grant operator or technician; grantableBy(isAdmin) is the one filter every grant route uses. contact.tier and case.reporter_tier (a creation-time snapshot) hold the stored strings, while a different human-facing WORD is only a label via report-fields.yml dashboard_ui.tier_labels which becomes TIER_LABELS. canSignOff is an EQUALITY test on purpose. The dashboard sign-off gate refuses in this order: technician authority, then mandatory minimum, then signoff_diagnosis. mandatory_minimum (with blocks_transition_to naming the done stages) is enforced at three code points: a case_transition REFUSAL, its tool description, and the prompt; it gates the AGENT tool surface only, so a dashboard operator closing from the console is not asked. selfCheckLoadBearingPromptContent composes the TOP rung's prompt and throws if an elevated instruction is missing or leaks downward. A record is held only by someone who can act on it: demotion or deleting a field login releases every open record via releaseCasesHeldBy, and no path assigns a record to the person whose own chat it is (isOwnConversation). Erasure reaches the role through _scrubRoleReferences, and retention never expires a channel:'system' singleton. Roles arrive only by operator assignment (POST /api/contacts/:id/tier or /register; normalizeMsisdn refuses an SA number that is not 27 plus 9 digits) or by a one-time code consumed by hooks/role-registration.js AFTER admission and BEFORE any turn, only when the message is nothing but a code (extractCode strict), so the model never sees it; a longer message has its code stripped. WRITE refuses an unrecognised tier; READ coerces a corrupt one to the lowest rung.
