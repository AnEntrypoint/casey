In casey, bootCasey() flattens freddie-base's cordis.patch.yml together with casey's own and calls freddie's boot(); casey mounts tools as defineTool() on ctx.tools, an LlmAdapter on ctx.llm, and the WhatsApp webhook on ctx.webServer at CASEY_WEBHOOK_PORT which defaults to 127.0.0.1:4001. Keep that port clear of the dashboard's 4000 or the process dies with EADDRINUSE and exit 44. freddie's patch YAML needs freddie's own schema loader (entryListSchema), not plain yaml.load. THE SAME WEBHOOK IS ALSO MOUNTED ON THE DASHBOARD'S PORT: routes/whatsapp-webhook.js mounts it there too, additively, registered FIRST ahead of compressResponses, express.json(), session middleware, CSRF and authGate(), so it is exempt from those and carries its OWN X-Hub-Signature-256 over the RAW bytes. The outbound adapter lookup fails silently when wrong: resolveAdapter reads casey.js's this.adapters (an object keyed by channel); freddie-bundle/src/platform discards handleInbound's return value, so adapter.send is the ONLY route an agent reply has to a contact, and bin/send-reply.js's makeSendReply REJECTS when the channel has no adapter.
